> **알아 둘 것** (2026-11-25): 화면은 `js/stockx.js` 가 그립니다 (`js/stock.js` · `js/opsboard.js` 의 재고 부분은 쓰이지 않음). 품목의 속성(이름 · 색 · 크기 · 원가 · 판매가)을 **화면에서 손으로 고치는 창은 없습니다** — 품목관리의 굿즈와 엑셀 불러오기에서 옵니다. 칸을 더하려면 어디서 입력할지부터 정합니다.


- **품목 = 품목관리의 굿즈 전부** (자동 · 「품목 추가」 버튼 없음 · `opsGoodsCache`). 굿즈에 없는 예전 품목도 「(굿즈 목록에 없음)」으로 보임
- **수량 두 곳**: **붕정**(창고) · **차방**(판매대) · 합계 · 최소(누르면 그 자리에서 고침 · 합계가 최소 이하면 빨강). 예전 기록의 `qty` 는 붕정 수량으로 읽음
- **움직임 기록** (위 버튼 · 여러 품목을 한 번에 · 날짜 · 메모 · 누가 · 언제 모두 남음):
  - **입고** = 붕정 + · **붕정에서 가져가기** = 붕정 − (어디로: 차방이면 차방 + / 행사 · 증정 · 기타는 메모)
  - **차방 판매** = 차방 − · **스마트스토어 판매** = 붕정 − (주문번호 · 수취인 메모)
  - **재고조사** = 붕정 · 차방에서 실제로 센 수 (시스템 수가 미리 들어 있음) → 다른 품목만 차이를 기록
- **기록 · 판매** 탭: 달 · 종류로 거름 · 그 달 **차방 판매 / 스마트스토어 판매 / 붕정에서 가져감** 합계(품목별) · 기록 표(날짜 · 종류 · 품목 · 수량 · 붕정 · 차방 변화 · 누가 · 메모)
- **정기 재고조사 2주마다**: 처음에 첫 조사일을 정함 → 그날이 되면(지나도) 재고관리 위와 **첫 화면 대시보드 맨 위에 모두에게** 「📋 정기 재고조사 날입니다」(누르면 재고관리 · `js/portal.js` `stockDueHTML`). 재고조사를 기록하면 다음 조사일 = 오늘 + 14일. 「날짜 바꾸기」로 고칠 수 있음
- **스마트스토어 발송 보고**는 메뉴에서 뺌 (`ship.html` 파일과 예전 발송 기록은 그대로 · 주소로는 열림)
- 저장: 공유 기록(calls) 통화 구분 「재고」 한 줄 = 품목 하나 `{kind:'stock', d:{name, wh, shop, min}, log:[{at, by, what, mv:{t(in · out · shop · web · count · min), n, dw, ds, to, memo, date}}]}` (최근 400개) · 설정 줄 id `stockcfg` `d:{cfg, cycle:14, next, last}`. 기록할 때는 먼저 최신을 받아 그 위에 더함. **서버 고칠 것 없음**
