# 예약 취소 요청 (`cancel.html`, 2026-11-19)

> 예전 README 의 **(번호 없음) 예약 취소 요청절** 을 그대로 옮긴 것입니다 (2026-11-25 문서 정리). 글 안의 「N절」은 [docs/README.md](../README.md) 의 「번호로 찾기」 표에서 파일을 찾습니다. 쓴 때의 설명이라 **코드와 다르면 코드가 맞습니다.**


- 직원이 예약 취소 담당자에게 취소 처리를 부탁하는 요청서 (예전 엑셀 「사유원 예약 취소 요청」을 옮김). 메뉴 › 예약보조 › 고객 응대 보조. 로그인해야 보임
- **전산 예약 붙여넣기** (2026-11-21, `parseErpCx` · `fillFromErp`): 요청서 맨 위 칸에 전산 예약 내역을 그대로 붙여 넣으면 방문일 · 예약자 이름 · 연락처 · 예약 사이트(홈페이지) · 예약 인원이 저절로 채워지고, 상품 · 인원 · 금액은 요청의 「전산 예약」(`erp`)으로 저장됨 (2026-11-23부터 「자세히」 칸은 없앰). 「비우기」면 붙여넣기 칸도 비움
- **취소 요청하기** 탭: 방문일(방문일 방식 날짜 칸) · 예약 사이트(홈페이지 · 네이버 · 키오스크 · 기타) · 예약자 이름 · 연락처 · 예약 번호 · 취소 내용(전체 환불 / 부분 취소) · 취소 사유(고객 직접 취소 불가 · 날씨 · 질병 · 사고 · 기타 — **하나만**, 「기타」면 사유 자세히 칸이 나옴 · 2026-11-23) · 증빙 서류(필요 없음 · 받음 · 받을 예정, 같은 줄에 파일 올리기) · 환불 계좌(가상계좌 결제 시 추가: 은행 고르기 · 계좌번호 · 예금주 본인 계좌 / 타인 계좌 + 예금주 이름(늘 보임 · 본인 계좌면 예약자 이름이 들어가고 고칠 수 있음, 고치기 전까지는 예약자 이름을 따라감 · 타인 계좌면 비우고 적음) — `accBank` · `accNo` · `accOwn` · `accName`, 목록용 글은 `acc`). 요청자 = 로그인 이름, 요청 시각 자동
- **부분 취소** (2026-11-23): 「예약 인원」(전산 예약 붙여넣기에서 · 고칠 수 있음)과 「취소할 인원」을 적음 → 예약 인원보다 많으면 빨간 에러 · 보내기 막음, 같으면 「전체 환불이 맞는지」 안내. 저장: `ppl` · `cnt` · `amt`=「2명 취소 (5명 → 3명)」
- **증빙 서류 올리기** (2026-11-23): 요청서 · 요청 목록 카드 모두에서 PDF · JPG · PNG(10MB 이하, 여러 개 · 종류가 비어 와도 확장자로 판단) — 서버 `upload`(단체 사업자등록증과 같음, 파일 이름 「방문일 예약자 취소 증빙」) → 요청의 `files:[{name,url,at,by}]`. 카드에서 올리면 바로 저장되고 증빙 서류가 「받음」으로
- **증빙 파일 주소에 보이는 이름** (2026-11-23): 브라우저는 탭 제목 · 저장 이름을 주소 끝에서 가져가서 예전에는 `fxxxx` 코드로 보였음 → 링크를 `/file/<id>/<화면에 보이는 이름>` 으로 만듦 (서버는 뒤 이름을 무시하고 id 로 찾음). 서버가 `api: 8` 이상일 때만 이름을 붙이므로 **`cloudflare/worker.js` 를 다시 붙여 넣고 Deploy 해야 켜짐** (그 전에는 예전 주소 그대로 · 링크가 깨지지 않음)
- **빠진 정보 · 나중에 채우기** (2026-11-23, `missOf`): 방문일 · 예약자 이름 · 연락처 · 예약 번호 · 취소 사유 · (부분 취소면) 취소할 인원 · (기타면) 사유 자세히 · (서류 받음 · 받을 예정이면) 증빙 서류 파일 · (환불 계좌를 적기 시작했으면) 은행 · 계좌번호 · (타인 계좌면) 예금주 이름. 예전 요청을 고칠 때 사유가 여러 개거나 지금 없는 사유면 「기타 + 자세히」로, 한 줄 계좌는 계좌번호 칸으로 불러옴. 이름 · 연락처 · 예약 번호 중 하나만 있으면 보낼 수 있고, 빠진 것이 있으면 확인 팝업. 요청 목록에서 처리 전 카드에 「⚠ 빠진 정보」 · 주황 테두리 · 「정보 채우기」(요청서에 불러와 고침 → 「고친 내용 저장」 · `edited`) · 「정보 덜 된 것만」 체크(건수). 환불 계좌는 결제 방법을 이 화면이 몰라 세지 않음
- **화면 배치** (2026-11-23): 탭 없이 2열 — 1열 「취소 요청하기」(380px로 좁게 · 스크롤해도 따라옴) · 2열 「요청 목록 · 처리」(남은 폭 모두). 1000px 보다 좁으면 위아래. 「정보 채우기」를 누르면 1열 요청서에 불러옴
- **요청 목록 · 처리**(머리 한 줄: 제목 + 처리 전 건수 · 처리 전/처리 완료/전체 · 정보 덜 된 것만 · 찾기 · 오른쪽 끝 「📥 엑셀 불러오기」, 그 아래 건수 요약): 표 하나, **요청 한 건 = 한 줄**(계속 쌓이므로 아래로 늘어남 · 머리줄 고정). 열: 상태(처리 전/완료 · 빠진 수 · 정보 채우기) · 예약자 · 연락처 · 방문일(12/5 (토), 올해가 아니면 해도) · 예약 번호 · 취소 내용 · 취소 사유 · 증빙 서류(+ 올리기 · 파일 이름은 말줄임) · 환불 계좌 · 요청 · 처리(메모 + 처리 완료 / 되돌리기). 빠진 칸은 빨간 「빠짐」. 1600px 화면에서 옆으로 밀리지 않게 맞춤. 처리 전(오래된 요청부터 · 노란 머리) · 처리 완료 · 전체 · 찾기(예약자 · 연락처 · 예약 번호 · 요청자). 카드마다 처리 메모 + 「처리 완료」(확인 팝업 → 처리한 사람 · 시각 · 메모) · 「되돌리기」 · 예약 번호를 누르면 복사. 30초마다 새 요청 · 처리를 받아 옴
- 「엑셀 불러오기」: 예전 엑셀 줄을 목록에 더함(같은 예약 번호 + 이름은 건너뜀, 맨 위 보기 줄 홍길동은 뺌, 처리 여부에 「완료」가 있으면 처리 완료)
