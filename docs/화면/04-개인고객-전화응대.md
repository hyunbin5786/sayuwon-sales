# 4. 개인고객 전화응대 (`personal.html`)

> 예전 README 의 **4절** 을 그대로 옮긴 것입니다 (2026-11-25 문서 정리). 글 안의 「N절」은 [docs/README.md](../README.md) 의 「번호로 찾기」 표에서 파일을 찾습니다. 쓴 때의 설명이라 **코드와 다르면 코드가 맞습니다.**


- **통화 기록 전체 = 내가 받은 오늘 통화가 기본** (2026-11-19): 「다른 사람 통화도 보기」(체크) · 「지난 통화 보기」 ↔ 「오늘 통화만 보기」(버튼)로 넓혀 봄. 검색하면 사람 · 날짜와 상관없이 모든 통화에서 찾음. 개수는 「n건 (전체 m건)」
- **단체고객 전화응대로 변경** (2026-11-19): 통화 기록 위 버튼. 듣다 보니 단체 문의인 통화 → 확인 팝업 뒤 같은 기록(같은 id)을 단체 예약 **예약상담**으로 바꿔 저장하고 단체 화면(`group.html?open=id`)에서 바로 엶. 성함 · 연락처 · 방문일 · 인원 · 문의 내용(메모) · 기록 · 직접 만든 과업은 그대로, 개인고객 자동 과업(문의 처리)과 구분은 뺌, 영업 담당 = 바꾼 사람, 결제 · 차량은 미정. 개인고객 목록에서는 빠짐 (`toGroup()`)
- **헤더**: 👤 이름 옆 **나의 할일**(빨간 `과업 n` = 마감이 오늘이거나 지난 내 과업, 팝업은 **개인** 탭부터) · 오른쪽 「전화문의 응대 매뉴얼 ↗」(노션) · **「통화 기록 전체」**
- **통화 기록** (왼쪽, 제목 줄 오른쪽에 「보고 글자 복사」 · 「저장 (Ctrl+S)」. **「＋ 새 통화」(Alt+N)는 단체 화면처럼 헤더**, 「전화문의 응대 매뉴얼」 바로 앞)
- **자동 저장** (단체 화면처럼): 고친 뒤 30초가 지나면 · 다른 창으로 가면 바로 저장 (새 통화도 문의 내용이나 고객 정보가 있으면). 저장 버튼 · Ctrl+S 는 그대로, 상태 칸에 「자동 저장 hh:mm」
- **＋ 새 통화**: 고치던 내용이 있으면 **바로 저장하고** 새 통화 (묻지 않음). 내용이 없어 저장할 수 없을 때만 「버리고 새 통화?」 (단체 화면도 같음: 업체나 방문일이 없을 때만 묻기)
- **저장 안 한 변경 = 노란 점 ●** (개인 · 단체 공통): 위 「저장」 버튼과 추후 과업마다 「저장」 버튼에 (그 과업에 저장 안 한 체크 · 메모 · 마감 · 제목 · 세부 과제가 있을 때만, 과업 메모는 치는 중에도). 저장되면 사라짐
- **추후 과업 접기**: 끝난 과업은 한 줄로 접히는데, **아래 하위 과업 · 세부 과제가 다 체크돼야** 접힘. 위 체크를 해도 아래가 남아 있으면 펼친 채로 (위 체크는 아래를 자동으로 체크하지 않음 · 위 체크를 풀면 아래도 모두 해제) (개인 · 단체 공통)
  - **구분**: 예약취소 · 결제링크 · 기타문의 등 중 하나 (다시 누르면 해제). **칩을 끌어서 순서 바꾸기**(모든 사람에게 같은 순서). **구분을 안 고르고 저장하면 「문의」**(목록에 없으면 맨 앞에 추가, 2026-11-18). **＋**로 추가, 칩 안 **×**로 삭제(기본 구분도). 추가 · 삭제는 공유 기록(id `pcats`, 통화 구분 `개인구분`)에 저장되어 모든 사람에게 같게. 삭제한 구분도 이미 저장된 통화에는 그대로 남고 점선 칩으로 보임
  - ~~보고전달자~~: 칸을 없앰 (2026-11-18). 예전 통화에 적힌 보고전달자는 기록 · 보고 글자에만 남고, 저장할 때 보고 글자 팝업은 자동으로 뜨지 않음 (「보고 글자 복사」 버튼으로)
  - ~~예약 여부~~: 칸을 없앰 (2026-11-18 · 안 씀). 예전 통화에 적힌 값은 기록에만 남음
  - 고객 이름 · 연락처 · **일시** (예전 이름: 방문 희망일 / 예약일) · 인원 · 문의 내용
- **보고 글자 복사** (카카오톡 보고용, **비어 있는 항목은 줄째 빠짐** · 첫 줄은 늘) → **미리보기 팝업**에서 글자를 고친 뒤 「복사하기」 (고친 글자는 복사에만, 통화 기록은 그대로 · Esc · 닫기). **보고전달자를 정하고 저장(버튼 · Ctrl+S)을 누르면 이 팝업이 자동으로 뜸** (같은 보고전달자로는 한 번만, 바꾸면 다시 · 자동 저장 때는 안 뜸)
  ```
  [구분]      (첫 줄은 구분만 — 받은 사람 이름 · 보고전달자는 넣지 않음, 2026-11-18 · 구분이 없으면 [문의])
  고객 이름 : 홍길동
  연락처 : 010-1234-5678
  일시 : 11/27(금)
  인원 : 2명
  문의내용 : …
  ```
- **추후 과업** (오른쪽): 단체 화면과 같은 모양 · 동작. 위에 고정된 「과업 직접 추가」(마감 기본 오늘), ⠿ 끌어서, 체크, 마감일, 「삭제」, 세부 과제(모두 체크하면 완료), 메모. 저장한 통화면 바로 저장 (메모는 칸을 벗어날 때)
  - **문의 내용 = 추후 과업** (2026-11-18): 통화를 처음 저장하면 **문의 내용 그대로가 과업 이름**인 추후 과업이 자동으로 생김 (마감 오늘, 처리되면 체크 · 여러 줄이면 「 / 」로 한 줄 · 문의 내용이 비었으면 「문의 처리 현황 점검」). 과업 이름을 직접 고치기 전까지는 문의 내용을 고치면 같이 바뀜. 지우면 다시 저장해도 다시 생기지 않음. 예전 모양(「문의 처리 현황 점검」 + 메모에 문의 내용)은 그 통화를 다시 저장할 때 이 모양으로 (`inqcheck`)
  - 과업마다 **「저장」** 버튼 (자동 저장은 그대로. 새 통화면 통화 전체를 저장)
  - 과업마다 오른쪽 **×** 버튼 → **「정말로 삭제할 건가요?」 확인 팝업**(삭제 · 취소, Esc = 취소) 뒤 삭제. 저장된 통화면 바로 시트에 반영 · 나의 할일에서도 빠짐
- **통화 기록 전체**: 모든 직원이 받은 개인고객 통화 표 (저장 · 고객(앞에 구분) · 연락처 · 방문일 · 인원 · 문의 · 남은 과업 · 삭제 · 맨 끝 **받은 사람**(초록)). 검색, 줄을 누르면 왼쪽에 열림
  - **삭제**: 사유를 골라야 삭제 (같은 통화를 두 번 저장 · 잘못 입력 · 테스트 · 다른 고객 기록에 잘못 저장 · 단체 예약으로 옮김 · 고객이 기록 삭제를 요청 · 기타(직접 입력)). 사유는 그 기록의 수정 기록에 남은 뒤 삭제. 왼쪽 통화 기록에는 삭제 버튼이 없습니다
  - **「삭제된 통화」**: 삭제 일시 · 삭제한 사람 · 사유 · 고객 · 연락처 · 방문일 · 문의 · 받은 사람 (보기 전용)
- **저장**: 공유 시트 `calls` 에 통화 구분 **개인고객**으로 (이름 → 고객 담당자, 방문일 → 방문일, 문의 → 통화 메모, 받은 사람 = 로그인한 이름). 구분 · 보고전달자 · 예약 여부 · 과업은 수정 기록 칸(JSON), 비고 칸에도 `구분 결제링크 / 보고전달자 김팀장 / 예약 여부 예약함`
- **전산 예약 정보 붙여넣기** (2026-11-27 · PC 에서만 — 휴대폰 폭 700px 아래에서는 버튼이 안 보임): 통화 기록 줄의 「전산 예약 정보 붙여넣기」 → 뜨는 창에 전산(관리자 사이트)의 예약 정보 글을 붙여 넣고 「채우기」
  - 읽는 항목: 방문일자(순번) · 상품정보 · 방문자정보 · 예약인원 · 테이블정보 · 상품금액 · 할인금액 · `*` 로 시작하는 할인 내역 줄 · 금액 · 등록. 항목 사이가 탭이 아니라 띄어쓰기여도 · 줄 순서가 달라도 · 빈 값이 있어도 읽음 (`js/personal.js` 의 `parseAdminText`)
  - 채우는 칸: 방문자정보 `이름(전화번호)` → 고객 이름 · 연락처 / 방문일자 → 일시 / 예약인원(맨 앞 숫자) → 인원. **비어 있는 칸만** 채우고, 이미 다른 값이 적힌 칸은 그대로 두고 알림글로 알림
  - 나머지는 문의 내용 아래에 「[전산 예약 정보]」 묶음으로 덧붙임 (방문일자(순번) · 상품 · 예약인원 · 테이블 · 상품금액 · 할인금액 · 할인 내역 · 금액 · 등록 — 읽은 것만). 있던 글은 지우지 않고, 같은 묶음을 두 번 붙이지 않음
  - 구분 · 채널은 건드리지 않음. 하나도 읽지 못하면 칸을 바꾸지 않고 창 안에 안내 글. 채운 뒤 저장은 평소대로(「저장」 · 30초 자동 저장) — 새 칸 · 새 DB 항목 없음
