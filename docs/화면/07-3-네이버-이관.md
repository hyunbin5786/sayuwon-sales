# 7-3. 네이버 이관 흐름 (`naver.html`, 2026-11-19)

> 예전 README 의 **7-3절** 을 그대로 옮긴 것입니다 (2026-11-25 문서 정리). 글 안의 「N절」은 [docs/README.md](../README.md) 의 「번호로 찾기」 표에서 파일을 찾습니다. 쓴 때의 설명이라 **코드와 다르면 코드가 맞습니다.**

- **엑셀이 먼저**: 1단계 = 네이버 예약자관리 엑셀(비밀번호) → 명단 · 환불(전액환불 · 취소는 뺌, 일부 환불은 인원을 뺌)까지 한 번에 최종 인원 → 2단계 일괄등록 → 3단계 최종검토- 엑셀로 안 되는 것(전화번호 앞자리가 가려짐 · 인원을 알 수 없음 · 이용일이 다름)은 1단계 위에 빨간 글로 알림 → **[엑셀이 안 될 때 · 텍스트로]**(예전 1단계 텍스트 정리)로 명단을 만들고 **[이 명단으로 최종 인원 →]**. 엑셀이 있으면 엑셀의 환불을 반영, 없으면 명단 그대로(직접 고침). 「엑셀로 명단 다시 만들기」로 되돌림- 코드: `excelRows()`(엑셀 → 명단) · `renderSrc2()`(어디서 만든 명단인지) · `state.source` = excel | text

- **4단계로 (2026-11-24 · 지금 흐름)**: **1 텍스트로 하기**(`#s1` · 처음 화면) → **2 엑셀로 확인하기**(`#s2` · 1단계 명단에 엑셀의 환불 반영 · 예매번호 · 인원 · 금액 점검 → 최종 인원) → **3 일괄등록**(`#s4`) → **4 최종검토**(`#s5`). 아래 2026-11-19 ~ 20 의 「엑셀이 먼저」 설명은 예전 흐름
  - 1단계 「2단계(엑셀로 확인)로 →」(`text2final`): 명단을 최종 인원으로 만들고 2단계로 (예전에는 바로 일괄등록). 엑셀이 아직 없으면 텍스트 명단 그대로(표에서 직접 고침) · 엑셀을 넣으면 환불이 반영됨
  - 1단계를 건너뛰고 2단계에서 엑셀만 넣으면 예전처럼 엑셀로 명단을 바로 만듦. 「← 1단계(텍스트)로」(`btnManual`)로 돌아감
  - 엑셀 오류: 1단계 텍스트 명단이 있으면 2단계에 남아 텍스트 명단 그대로 최종 인원 · 없으면 1단계로. 리셋하면 1단계로
- **엑셀 오류면 바로 텍스트로** (2026-11-20): 네이버 엑셀을 읽다가 오류(비밀번호가 맞지 않습니다 등)가 나면 1단계 「텍스트로 하기」로 바로 넘어가고 붙여넣기 칸에 커서 (엑셀 칸에는 「엑셀 오류: … — 텍스트로 하기로 넘어갔습니다」). 비밀번호를 안 넣었으면 예전처럼 비밀번호 칸
- **텍스트로 하기: 버튼 위치** (2026-11-20): 정리 결과 제목 오른쪽에 「저장하기」(흰 바탕) · 「이 명단으로 최종 인원 →」(초록)를 나란히 — 예전엔 최종 인원 버튼이 맨 아래
- **텍스트로 하기 → 바로 일괄등록** (2026-11-20): 「이 명단으로 최종 인원 →」을 누르면 최종 인원 화면 · 「2단계(일괄등록)로 가기」를 거치지 않고 바로 일괄등록 (최대 인원을 넘으면 예전처럼 확인 팝업). 엑셀 흐름은 그대로
