# 함께 고치는 사람의 PC 세팅 순서 (Claude 에게 주는 지시)

2026-11-26 에 한 사람의 PC 를 실제로 세팅한 순서를 그대로 적은 것입니다. **다른 사람의 PC 도 똑같이 세팅하기 위한 글이고, 읽는 쪽은 그 사람의 Claude 입니다.** 백업 설정은 여기서 다루지 않습니다 (맨 아래 「백업」).

**사람이 처음에 하는 말** (빈 폴더에서 Claude Code 를 열고):

> https://github.com/hyunbin5786/sayuwon-sales 을 받아서 `docs/개발/함께-고치는-사람-세팅-순서.md` 대로 내 PC 를 세팅해 줘.

---

## Claude 가 지킬 것

- `CLAUDE.md` 를 끝까지 읽고 따른다. 이 글은 그 위에 얹는 「세팅 순서」일 뿐이다.
- **사번 · 열쇠 값은 대화로 받지 않는다.** 사람이 메모장으로 파일에 직접 적는다. Claude 는 그 파일의 내용을 화면에 찍지 않고, 「채워졌는지」만 길이로 본다.
- 이 저장소는 공개다. 이름 · 사번 · 열쇠 · 고객 자료를 커밋하지 않는다.
- 아래 표의 「사람에게 받을 것」을 **한 번에 모아서** 묻는다. 하나씩 여러 번 묻지 않는다.

## 1. 사람에게 받을 것 (한 번에 묻는다)

| 번호 | 받을 것 | 어떻게 받나 | 2026-11-26 에 받은 모양 |
|---|---|---|---|
| ① | Git 을 설치했는지 | 대화로 「설치했어」 | 없어서 https://git-scm.com/download/win 에서 설치하게 함 |
| ② | 저장소를 둘 폴더 | 대화로 폴더 경로 | 바탕 화면 아래의 빈 폴더 경로 |
| ③ | GitHub 에 올릴 권한이 있는지 | 대화로 「있어」 | 저장소 주인이 Collaborator 로 초대 → 초대 메일 수락 |
| ④ | 멤버로 등록돼 있는지 | 대화로 「돼 있어」 | 배포 사이트에 이름 + 사번으로 로그인되면 된 것 |
| ⑤ | 저장(커밋)에 남길 이름 | 대화로 (별명도 됨) | 별명 하나 |
| ⑥ | GitHub 아이디 | 대화로 | 아이디 하나 (메일 주소가 아님) |
| ⑦ | 이름 · 사번 | **메모장으로 파일에** (`tools\my-login.json`) | — |
| ⑧ | 열쇠 (`TEST_SYNC_KEY` 값) | **메모장으로 파일에** (`tools\test-sync-key.txt`) | 먼저 세팅한 사람에게 직접 받음 |
| ⑨ | Cloudflare 계정에 초대됐는지 | 대화로 (서버 코드를 고칠 사람만) | 계정 주인이 초대 |

③ · ④ · ⑨ 는 Claude 가 대신 확인할 수 없다. 사람의 답을 그대로 믿고 진행하고, 나중에 올리기 · 로그인에서 막히면 그때 다시 본다.

## 2. 순서

### 2-1. Git 확인

`git --version` 이 되는지 본다. 안 되면 사람에게 설치를 부탁하고 기다린다 (설치 뒤에는 새 명령 창에서 잡힌다).

### 2-2. 저장소 받기

사람이 알려 준 폴더(②)가 **비어 있는지 먼저 본 뒤** 그 안에 받는다.

```powershell
git clone https://github.com/hyunbin5786/sayuwon-sales.git "<사람이 알려 준 폴더>"
```

```powershell
git -C "<그 폴더>" checkout test
```

- 세션을 그 폴더로 옮긴다 (Claude 데스크톱 앱이면 작업 폴더 바꾸기 도구). 옮기면서 임시로 받아 둔 파일(압축 파일 · 읽기용 사본)이 저장소 폴더로 따라 들어오면 지운다 — `git status --short` 에 `??` 로 보인다. **커밋하지 않는다.**
- 폴더가 OneDrive 안이면 한 번 알린다: 사번이 든 로그인 파일과 열쇠 파일이 OneDrive 에도 올라가니 그 폴더를 남과 공유하지 말 것.
- 사람에게 「다음부터는 Claude Code 에서 이 폴더를 열어 주세요」 라고 알린다 (그래야 `CLAUDE.md` 가 자동으로 읽힌다).

### 2-3. 저장(커밋)에 남길 이름

⑤ · ⑥ 으로 **이 폴더에만** 정한다 (`--global` 을 붙이지 않는다). 메일은 GitHub 의 비공개 주소를 쓴다.

```powershell
git config user.name "<⑤ 별명>"
```

```powershell
git config user.email "<⑥ GitHub아이디>@users.noreply.github.com"
```

### 2-4. 상태 점검

```powershell
powershell -ExecutionPolicy Bypass -File tools\check.ps1
```

아무것도 바꾸지 않는다. 종료 코드 3 은 오류가 아니라 「먼저 할 일이 있다」는 뜻이다. 결과를 쉬운 말로 알린다. 「백업」이 할 일로 나오는 것은 맨 아래 「백업」을 따른다.

### 2-5. 이름 · 사번 넣기 (⑦)

`tools\my-login.json` 이 없으면 빈 틀을 만든다 (내용: `{ "name": "", "emp": "" }` · UTF-8). 사람에게 이렇게 시킨다:

```powershell
notepad tools\my-login.json
```

> `"name": ""` 의 따옴표 사이에 이름(배포 사이트 로그인에 쓰는 그대로), `"emp": ""` 의 따옴표 사이에 사번을 적고 **Ctrl + S** 로 저장해 주세요. 사번은 저에게 말하지 마세요.

적었다고 하면 **내용을 찍지 말고** 채워졌는지만 본다:

```powershell
$j = Get-Content tools\my-login.json -Raw -Encoding UTF8 | ConvertFrom-Json; "name: $([bool]$j.name) / emp: $([bool]$j.emp)"
```

2026-11-26 에는 처음에 저장이 안 돼 비어 있었다. 둘 다 `True` 가 나올 때까지 다음으로 넘어가지 않는다.

### 2-6. 열쇠 넣기 (⑧)

```powershell
notepad tools\test-sync-key.txt
```

> 「새로 만드시겠습니까?」에 예를 누르고, 받은 열쇠 한 줄만 붙여 넣고 저장해 주세요. 저에게 보여 주지 않으셔도 됩니다.

**열쇠가 맞는지 확인** — 테스트 서버에, 없는 표 이름으로 요청을 한 번 보낸다. 서버는 열쇠를 먼저 보고 그다음에 표 이름을 보므로, 아무것도 바뀌지 않고 답으로 알 수 있다.

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12; $key = ([IO.File]::ReadAllText((Resolve-Path tools\test-sync-key.txt))).Trim(); $wc = New-Object Net.WebClient; $wc.Encoding = New-Object Text.UTF8Encoding $false; $wc.UploadString('https://sayuwon-api-test.serendipity5786-9e7.workers.dev/', 'POST', ('{"action":"mirror","key":' + (ConvertTo-Json $key) + ',"table":"__check__"}'))
```

| 답 | 뜻 |
|---|---|
| `"error":"bad_table"` | **열쇠가 맞다** (열쇠는 통과했고 표 이름에서 멈춤) |
| `"error":"bad_key"` | 열쇠가 서버의 값과 다르다 — 준 사람에게 다시 받는다 |

- 주소는 **꼭 `sayuwon-api-test`** (테스트 서버). 배포 서버에는 보내지 않는다.
- `"step"` 을 넣지 않는다. `"step":"begin"` 은 테스트 DB 를 통째로 비운다.
- 열쇠 값은 화면에 찍지 않는다.

### 2-7. GitHub 에 올릴 수 있는지 (③)

브라우저로 github.com 에 로그인돼 있는 것과 **이 PC 의 Git 이 올릴 수 있는 것은 별개**다. 처음 올릴 때 Git 이 로그인 창을 띄워야 하는데, Claude 의 명령 창은 그 창을 못 띄우게 돼 있어(`GCM_INTERACTIVE=never`) 이렇게 실패한다:

```
fatal: Cannot prompt because user interactivity has been disabled.
```

올리는 명령 앞에 이것을 붙이면 된다 (명령마다 다시 붙인다):

```powershell
$env:GCM_INTERACTIVE='always'; git push origin test
```

로그인 창이 뜨면 사람이 ⑥ 의 계정으로 로그인한다. 한 번 하면 그 PC 에 기억된다. 권한(③)이 없으면 여기서 `403` 으로 막힌다 — 저장소 주인에게 Collaborator 초대를 부탁하게 한다.

올릴 것이 없으면 세팅 단계에서 억지로 올리지 않는다. 첫 수정을 올릴 때 확인된다.

### 2-8. Cloudflare (⑨ · 서버 코드를 고칠 사람만)

Claude 는 Cloudflare 화면을 볼 수 없다. 사람에게 확인하게 한다: 초대받은 계정으로 Cloudflare 에 로그인 → 왼쪽 **Workers & Pages** 에 `sayuwon-api` · `sayuwon-api-test` 가 보이면 된 것.

초대는 **계정 주인**이 한다: Cloudflare › **Manage Account** › **Members** › **Invite** › 초대받을 사람의 메일 · 권한(Administrator 가 가장 간단). 무료 계정에서도 된다. 초대받을 사람은 먼저 그 메일로 Cloudflare 에 가입해 둔다.

## 3. 여럿이 같은 `test` 에 올린다

2026-11-26 부터 `test` 브랜치에는 여러 사람이 각자 다른 기능을 고쳐 올린다 (운영팀이 정함).

- **고치기 전 · 올리기 전에 먼저 받는다**: `git pull --ff-only`. 내 저장(커밋)이 이미 있어 안 되면 `git merge origin/test` 로 합친다 (지난 커밋을 고쳐 쓰는 방법은 쓰지 않는다 — 철칙 10).
- **`docs/바뀐-것-기록.md` 는 자주 겹친다** (모두 맨 아래에 한 줄씩 적으므로). 겹치면 **양쪽 줄을 모두 살린다.**
- **`docs/코드-지도.md` 는 손으로 합치지 않는다.** 합친 뒤 `tools\map.ps1` 로 다시 만든다.
- 남의 커밋이 올라와 있다고 매번 사람에게 경고하지 않는다. 다만 아래 둘은 남의 작업에 영향을 주므로 **무엇이 영향을 받는지 보여 주고 확인받는다**:
  - 「푸시」 — `test` 에 있는 것이 전부 `main`(배포)으로 간다. 남의 덜 끝난 작업도 같이 간다. `git log --oneline origin/main..origin/test` 를 보여 준다.
  - 「새 개발 시작」 — 테스트 DB 를 비우고 다시 채운다. 남이 테스트에 넣어 둔 자료가 사라진다.

## 4. 세팅이 끝났는지

`tools\check.ps1` 을 다시 돌려 아래가 「좋음」인지 본다.

| 줄 | 좋음의 뜻 |
|---|---|
| 브랜치 | `test` |
| Git 이름 | 2-3 을 했다 |
| 내 로그인 | 2-5 를 했다 |
| 열쇠 | 2-6 을 했다 (파일이 있다는 것까지만 본다 — 값이 맞는지는 2-6 의 확인으로) |
| 배포 서버 · 테스트 서버 | 응답함 |

끝나면 사람에게 말한다: 무엇을 했는지 · 무엇을 확인했는지 · 확인하지 못한 것(③ · ④ · ⑨ 처럼 사람의 답만 들은 것).

## 백업

**백업은 이미 걸려 있다** — 개발 담당 PC 한 대가 매주 수요일 9시에 받는다 (저장소 `README.md` 맨 위). 그래서:

- 함께 고치는 사람의 PC 에서는 `tools\check.ps1` 이 「백업: 할 일」 이라고 나와도 **새로 걸지 않는다.** 사람에게 「백업은 담당 PC 에 이미 걸려 있어 이 PC 에는 걸지 않습니다」 라고 한 번만 알린다.
- 사람이 「이 PC 에도 걸어 줘」 라고 하면 그때 `CLAUDE.md` 2절대로 건다.
- 자료에 손대는 큰 일(철칙 8)을 하기 전에 한 번 받아 두는 것은 누구의 PC 에서든 그대로 지킨다.
