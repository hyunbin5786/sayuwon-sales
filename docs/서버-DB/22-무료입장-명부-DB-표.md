# 22. 무료입장 명부를 DB 표로 (`clergy` · 2026-11-23)

> 예전 README 의 **22절** 을 그대로 옮긴 것입니다 (2026-11-25 문서 정리). 글 안의 「N절」은 [docs/README.md](../README.md) 의 「번호로 찾기」 표에서 파일을 찾습니다. 쓴 때의 설명이라 **코드와 다르면 코드가 맞습니다.**


**왜**: 명부(엑셀 283명 · 2026-05 ~ 11월)를 공유 기록 한 줄에 4만 자씩 묶어 넣던 것을, DB 의 표 하나에 한 사람 한 방문 = 한 줄로 넣음. 추가 · 지우기가 한 줄씩이라 남이 고친 것을 덮어쓰지 않고, 회차를 서버가 세며, 다른 화면 · 다른 DB 로도 그대로 조회할 수 있음

- **표** `clergy` (`cloudflare/schema.sql`): `id` · `visit_date` · `org` · `name` · `pos` · `phone` · `note` · `turn` · `who`(이름 띄어쓰기 뺌 `|` 연락처 숫자 — 회차 셀 때) · `added` · `by` · `updated` · `deleted`(지운 일시 + 사람 · 줄은 남김). 서버가 처음 쓸 때 표가 없으면 스스로 만듦 (`ensureClergy` — D1 Console 에서 따로 실행하지 않아도 됨)
- **서버 동작** (`cloudflare/worker.js` · 11절 표): `clergyList`(지워지지 않은 줄 전체 · SQLite 가 JSON 을 만들어 그대로 보냄) · `clergyAdd`(넣는 문장 안에서 그해 같은 `who` 수 + 1 = 회차 → 둘이 같이 넣어도 맞음) · `clergyDel` · `clergyImport`(`replace` 면 지금 명부에 지운 표시 → 엑셀 줄을 `json_each` 로 **SQL 한 문장**에 모두 넣음 · 한 묶음이라 중간에 실패하면 되돌아감). 바꾸면 `rev` 를 올려 다른 컴퓨터 화면이 바로 다시 받음
- **화면** (`js/clergy.js`): 열 때 · 다른 컴퓨터에서 바뀔 때(`SY.live.onRev`) · 5분마다 명부 전체를 받아 화면 안에서 찾음. 엑셀 불러오기 · 새로 추가 · × 지우기는 위 동작으로
- **예전 묶음 옮기기**: 처음 열 때 `moved`(kv `clergy_moved`)가 없으면 예전 `clergy0` … 의 명부를 DB 로 옮기고 그 묶음은 지움 (지워진 기록에 남음). 엑셀을 한 번이라도 불러오면 `moved` 가 켜짐
- **서버를 아직 새로 올리지 않았으면** (`bad_action`): 예전 묶음을 **보기만** 하고 추가 · 엑셀 불러오기 버튼이 꺼짐 + 「서버를 새로 올려야…」 표시
- **백업 · 되살리기**: `export` 표 목록 · `tools/backup.ps1` · `tools/export.html` 에 `clergy` 더함, `tools/restore.html` → `import` 의 `clergy`(줄 그대로)

**할 일 (사람 · 한 번)**: Cloudflare → Workers & Pages → `sayuwon-api` → Edit code → `cloudflare/worker.js` 내용을 통째로 붙여 넣고 Deploy (18-2절 3번과 같음). 그 뒤 명부 화면을 열어 「엑셀 불러오기」로 명부 엑셀을 한 번 넣음

**확인 (로컬 `?mock=cf`)**: 예전 묶음 2명 → 처음 열 때 DB 로 옮겨지고 묶음은 지워짐 · 명부 엑셀 → 283명 (방문일 모두 날짜 모양 · 예전 2명은 지운 표시) · 같은 사람을 그해 한 번 더 넣으면 서버가 「2회차」 · 새로 추가 → 1회차 · 찾기 · × 지우기 · `export clergy` · 콘솔 오류 없음. **진짜 D1 에서는 서버를 올린 뒤 확인**

### 22-1. 화면을 2열로 (2026-11-23 추가)

- **1열 = 「새로 추가」 칸만** (늘 열려 있음 · 추가만 함). 방문일 · 소속 · 이름 · 직책 · 연락처 → 「저장」. 저장하면 방문일 · 직책은 두고 소속 · 이름 · 연락처를 비움 (「비우기」도 같음). 회차 · 소속 경고는 예전과 같음 · 화면을 내려도 따라옴(sticky)
- **2열 = 명부 표** (엑셀 불러오기로 넣은 명부 · 찾기 · 올해만 · × 지우기). 예전의 「＋ 새로 추가」 버튼은 없앰
- 너비 900px 아래(휴대폰 등)에서는 1열 위 · 2열 아래로. `main` 이 `prep.css` 의 2열 grid 라 `.cl-cols` 가 한 줄을 통째로 씀 (`css/clergy.css`)

### 22-2. 같은 사람 = 소속 · 이름 · 연락처 · 소속 자동 확인 → 없으면 관리자 승인 (2026-11-23 추가)

- **회차 · 올해 횟수는 소속 · 이름 · 연락처가 모두 같을 때만** 셈. 비교할 때 띄어쓰기 · 앞의 「(재)」「천주교」는 무시, 연락처는 숫자만 (`js/clergy.js` `who` · `cloudflare/worker.js` `clWho` — 두 곳 규칙이 같아야 함). 서버는 처음 쓸 때 예전 규칙(이름 · 연락처)으로 적힌 `who` 를 한 번 다시 적음 (`clergyRewho` · kv `clergy_who`='2')
- **소속 자동 확인**: 대구대교구 누리집은 프로그램 요청을 방화벽(WebKnight)으로 막아 직접 검색할 수 없음 (2026-11-23 확인) → 누리집에서 옮겨 둔 목록 `js/clergyorg.js` + 명부에 이미 있는 소속에서 찾음. 소속을 치면 칸 아래에 「✓ 대구대교구 ○○ 본당」 또는 「대구대교구에서 찾지 못함 — 저장할 때 관리자 승인」
- 찾지 못하면 저장할 때 팝업 (검색이 안 되는 것일 수도 있으니 「천주교 대구대교구 기관 검색」 링크로 확인 안내) → **「승인하고 등록」**을 누르면 그대로 등록, 비고에 「소속 승인 (누른 사람)」. 관리자 권한을 따로 두지는 않음 — 누른 사람 이름이 남음. 한 번 등록된 소속은 다음부터 명부에 있는 소속으로 통과
- 1열 안내 글은 「소속 확인: 천주교 대구대교구 기관 검색」 링크만 남김
- 서버 쪽(`clWho` · `clergyRewho`)이 바뀌었으므로 **`cloudflare/worker.js` 를 다시 붙여 넣어야** 서버가 세는 회차도 새 규칙이 됨 (화면의 미리보기 · 경고는 바로 새 규칙)
