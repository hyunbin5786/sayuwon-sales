# 19. 틀린 로그인 횟수 제한 · 견적서 서버 합치기 (2026-11-23)

> 예전 README 의 **19절** 을 그대로 옮긴 것입니다 (2026-11-25 문서 정리). 글 안의 「N절」은 [docs/README.md](../README.md) 의 「번호로 찾기」 표에서 파일을 찾습니다. 쓴 때의 설명이라 **코드와 다르면 코드가 맞습니다.**


### 19-1. 틀린 로그인 횟수 제한 (`cloudflare/worker.js` `noteFail` · `isBlocked`)

- 같은 곳(IP)에서 **10분 안에 멤버 목록에 없는 「이름 + 사번」을 서로 다른 것으로 8번** 보내면 그곳을 **15분 동안 막음**. 막힌 동안은 맞는 이름 · 사번도 받지 않음(`too_many`) → 사번을 하나씩 넣어 보며 맞추는 시도를 막음
- 같은 틀린 값을 되풀이하는 것은 한 번으로 셈 (멤버에서 빠진 사람의 브라우저가 30초마다 다시 묻는 것 때문에 사무실 전체가 막히지 않게). 로그인하지 않은 요청과 로그인 없이 되는 동작(멘트 보기 · 예약 현황 공유 · 고객 견적 요청 · 품목 목록 읽기)은 세지도 막지도 않음
- 로그인 화면에는 「틀린 로그인이 여러 번 이어져 잠시 막혔습니다. 15분쯤 뒤에 다시 해 주세요.」, 다른 화면은 「연결 끊김 · 다시 시도 중」으로 보이다가 풀리면 저절로 이어짐
- 사무실은 보통 인터넷 주소(IP) 하나를 같이 쓰므로, **사무실 안에서 누가 8가지 틀린 값을 넣으면 사무실 전체가 15분 막힘**. 급하면 Cloudflare D1 콘솔에서 `DELETE FROM kv WHERE k LIKE 'fail:%';` 를 실행하면 바로 풀림. 숫자는 `FAIL_WINDOW` · `FAIL_MAX` · `FAIL_BLOCK`
- 함께 고친 것: 첫 화면 로그인이 서버의 `bad_key` 답을 「예전 서버라 확인 기능이 없음」으로 보고 통과시키던 것을 없앰 (`bad_action` 일 때만)

### 19-2. 견적서 서버를 같은 서버로

- 예전: 품목 관리에서 바꾼 것 · 견적서 발급 내역은 따로 있는 구글 Apps Script(`shared-catalog.gs` · 저장소 `sayuwon-invoice-quotation`)에 있었고 **로그인 확인이 없었음** (주소만 알면 고객 이름 · 금액이 든 발급 내역을 읽고 쓸 수 있었음)
- 지금: 같은 Worker 의 동작 두 개. 화면 코드는 그대로 `SY.quote.get()` · `SY.quote.post()` — `js/common.js` 의 `SY_BACKEND.quoteGet` · `quotePost` 만 바뀜

| action | 로그인 | 내용 |
|---|---|---|
| `quoteGet` (history 없음) | 필요 없음 | → `{data:{edits, added}, historyApi:3}` 품목 관리에서 바꾼 것 (가격표에 쓰는 값 · 로그인 없이 보는 예약 현황 공유 화면도 읽음) |
| `quoteGet` + `history:1, limit` | 필요 | → `{history:[…]}` 발급 내역, 최근 것부터 |
| `quotePost` + `ops` · `history` · `cancel` | 필요 | 품목 고치기(set · setAdded · add · delAdded · reset · replace) → `{data}` / 발급 내역 더하기(같은 id 는 한 번만) → `{saved}` / 발급 취소 · 취소 철회 → `{canceled}` |

- 저장: 품목 = `kv` 표의 `catalog` 한 줄(JSON) · 발급 내역 = `quote_history` 표 (한 줄 = 한 번 발급, `data` 에 내역 전체 JSON)
- 옮기기: `tools/migrate.html` 이 예전 견적서 서버에서 읽어 옴. 품목 목록은 새 서버에 아직 없을 때만, 발급 내역은 새 서버에 없는 id 만 더함 (다시 돌려도 새 서버에서 한 발급 취소 · 품목 수정을 지우지 않음)
- **예전 견적서 사이트(sayuwon-invoice-quotation)는 계속 예전 Apps Script 를 씀** → 그 사이트에서 낸 발급 내역 · 고친 품목은 이 시스템에 안 보임 (그 반대도). 이 시스템의 `document/` 만 쓸 것
- 서버 코드 · 표를 고쳤으므로 올리는 순서: ① D1 콘솔에서 `quote_history` 표 만들기 ② Worker 에 새 `worker.js` 붙여 넣고 Deploy ③ `migrate.html` 로 견적서 자료 옮기기 ④ 화면 코드 푸시. (①②를 먼저 해도 예전 화면은 그대로 돎)
- 로컬 시험(`?mock=cf`): 품목 읽기는 로그인 없이 · 발급 내역 읽기/쓰기는 로그인 없으면 `bad_key` · 품목 op 여섯 가지 · 같은 발급 두 번 → 한 줄 · 발급 취소 · 최근 것부터 · `limit` · 품목 관리 화면에서 가격 고치기(`quotePost:set` → 「저장했습니다」) · 단체 화면 가격표 불러오기 · 틀린 로그인 8가지 → 9번째부터 `too_many`(맞는 로그인도) · 다른 IP 는 정상 · 같은 틀린 값 3번은 1번으로 · 옮기는 도구 두 번 돌리기 — 모두 정상
