이 시스템 — 어떻게 생겼고, 어떻게 고치나

코드를 몰라도 됩니다. 이 시스템은 Claude 에게 말로 시켜서 고칩니다. 「어떻게 생겼는지」와 「어떻게 시키는지」만 알면 됩니다.

[1] 이 시스템은 식당처럼 생겼습니다

손님은 홀에서 메뉴판을 보고 주문합니다. 주문서가 주방으로 넘어가고, 주방은 창고에서 재료를 꺼내 요리를 내보냅니다. 우리 시스템도 똑같이 네 칸입니다.

위 화살표가 주문, 아래 화살표가 답입니다. 화면은 창고에 직접 들어가지 못하고 꼭 주문서를 거칩니다.

말식당으로 치면우리 시스템에서는
프런트엔드홀과 메뉴판브라우저에 보이는 화면. 버튼 · 표 · 달력.
백엔드주방보이지 않는 곳에서 로그인을 확인하고 저장 · 조회를 처리하는 서버.
API주문서화면이 서버에 부탁할 때 쓰는 정해진 양식. 「목록 주세요」 「이거 저장해 주세요」.
DB창고 · 장부예약 · 통화 · 할일 · 멤버가 실제로 적혀 있는 곳. 딱 한 곳뿐입니다.
GitHub레시피 책 보관함코드를 저장하는 곳. 누가 언제 무엇을 바꿨는지 모두 남아 언제든 되돌릴 수 있습니다. 화면도 여기서 띄워 줍니다.
Cloudflare주방과 창고가 있는 건물서버와 DB 가 들어 있는 곳. 자료는 전부 여기 있습니다.

[2] 가게가 두 곳입니다 — 본점과 연습 주방

손님이 있는 본점에서 새 요리를 시험하지 않습니다. 똑같이 생긴 연습 주방에서 먼저 만들어 보고, 괜찮으면 본점 메뉴에 올립니다.

코드는 테스트 → 배포로, 자료는 배포 → 테스트로만 갑니다. 테스트에서 넣은 가짜 예약이 진짜 DB 로 넘어가는 일은 없습니다.

[3] Claude 에게 말로 시켜서 고칩니다

처음 한 번 — 내 PC 준비. Claude Code 를 열고 아래 한 문장을 그대로 붙여 넣습니다. 나머지는 Claude 가 한 단계씩 안내합니다.

https://github.com/hyunbin5786/sayuwon-sales 을 받아서 docs/개발/함께-고치는-사람-세팅-순서.md 대로 내 PC 를 세팅해 줘.

다음부터는 Claude Code 에서 sayuwon-sales 폴더를 열고 시작합니다. 그래야 Claude 가 일하는 규칙을 스스로 읽습니다. 로그인 계정 · 비밀번호 · 열쇠는 여기 적지 않습니다 — 담당자에게 따로 받습니다.

고칠 때마다 — 네 걸음.

이렇게 말하면 잘 됩니다.

  • 어느 화면인지 주소를 붙입니다. 테스트 사이트 주소를 그대로 복사해 넣으면 됩니다.
  • 지금 어떤지, 어떻게 되면 좋겠는지를 평소 말투로 적습니다.
  • 한 번에 하나씩. 기능 하나에 요청 하나가 가장 빠르고 안전합니다.

외워 둘 말.

이렇게 말하면Claude 가 하는 일
「지금 상태 어때?」저장 안 된 수정 · 테스트와 배포의 차이 · 백업 상태를 점검해 알려 줍니다.
「푸시」테스트에서 확인한 것을 배포 사이트로 올립니다. 이 말을 하기 전에는 배포 사이트가 바뀌지 않습니다.
「되돌려줘」방금 고친 것을 예전으로 돌립니다. 기록은 지우지 않고 남깁니다.
「백업 받아 줘」자료 전체를 내 PC 로 한 번 받아 둡니다.
「붙여 넣었어」서버 코드를 Cloudflare 에 붙여 넣은 뒤 하는 말. Claude 가 올라갔는지 확인합니다.
가끔 내 손이 필요한 때 — 서버를 고쳤을 때

화면은 올리면 1~2분 안에 저절로 바뀝니다. 서버(주방)만은 사람이 Cloudflare 에 직접 붙여 넣어야 합니다. Claude 가 붙여 넣을 내용을 복사해 두고, 어디를 누르는지 알려 줍니다.

  • 1 Cloudflare 에 로그인하고, 왼쪽 위 계정을 우리 계정으로 바꿉니다.
  • 2 Workers & Pages → 서버 이름을 누릅니다. 테스트는 sayuwon-api-test, 배포는 sayuwon-api.
  • 3 Edit code → 전체 지우고 붙여넣기 → Deploy.
  • 4 Claude 에게 「붙여 넣었어」.

우리끼리의 약속 (헌법).

  • 고치는 곳은 늘 테스트. 배포 사이트는 「푸시」로만 바뀝니다.
  • 시작할 때 Claude 가 남이 올린 것을 받고, 배포 DB 를 테스트 DB 로 다시 가져옵니다. 테스트에 넣어 둔 시험 자료는 이때 사라집니다.
  • 끝낼 때 무엇을 바꿨는지 README 의 「최근 바뀐 것」에 한 줄 남깁니다. 다음 사람이 그것을 읽고 시작합니다.
  • 자료는 지우지 않습니다. 삭제는 「지운 표시」만 하고, 잘못 들어간 예약은 화면에서 삭제합니다.
  • 이름 · 사번 · 고객 정보 · 비밀번호는 코드에 넣지 않습니다. 코드 저장소는 누구나 볼 수 있습니다.
Claude 가 「확인하지 못했습니다」라고 하면 그 부분은 테스트 사이트에서 직접 눌러 보세요. Claude 는 가짜 자료로만 확인하고, 진짜 자료가 든 화면은 사람이 봅니다.

[4] 백업 — 자료는 DB 한 곳에만 있습니다

무엇지금 상태
매주 자동 백업매주 수요일 9시, 개발 담당 PC 가 자료 전체를 받아 사내 공유 폴더에 저장합니다 (2026-11-26 부터 · 최근 8개). 서버 쪽에는 자동 백업이 없습니다.
지금 한 번 받기Claude 에게 「백업 받아 줘」. 또는 로그인한 브라우저에서 직접 내려받기 를 열어 「내려받기」.
되살리기백업에서 되살리기 에서 백업 파일을 고릅니다. 모두가 쓰는 자료를 바꾸는 일이라 담당자와 함께 합니다 (열쇠가 필요합니다).
  • 큰 일을 하기 전에는 먼저 한 번 받습니다 — 서버의 저장 방식을 바꿀 때 · 자료를 한꺼번에 고칠 때 · 되살리기 전.
  • 담당 PC 가 바뀌면 새 담당자가 자기 PC 에 가장 먼저 다시 겁니다. Claude 에게 「백업 걸어 줘」.
  • 백업 파일에는 고객 연락처와 멤버의 이름 · 사번이 들어 있습니다. 메일 · 메신저로 보내지 말고 정해진 폴더에만 둡니다.
