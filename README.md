주소: https://hyunbin5786.github.io/sayuwon-sales/

사유원 예약 · 운영팀이 전화 응대 · 단체 예약 접수 · 다음날 응대 준비 · 견적서 발급 · 할 일 관리 · 분실물 · 사고 · 재고를 한곳에서 하는 웹 시스템입니다. 화면은 GitHub Pages(정적 HTML · CSS · JS), 공유 기록은 구글 시트(Apps Script 웹 앱)에 있습니다.

- HTML에는 화면 틀만, 모양은 `css/`, 동작은 `js/`에 있습니다. 로그인 확인처럼 화면이 그려지기 전에 돌아야 하는 몇 줄만 HTML `<head>` 안에 남겨 두었습니다
- **CSS · JS를 고치면 HTML의 `?v=날짜` 를 바꿔 주세요** (예: `js/group.js?v=20261114` → `?v=20261115`). 그래야 브라우저가 예전 파일을 쓰지 않습니다
- 단체 · 개인고객 화면은 품목 · 가격을 `document/js/document.js` 를 읽어서 가져옵니다 (견적서 코드의 `CATALOG_RAW` 등). 견적서 코드를 옮기거나 이름을 바꾸면 `js/group.js` · `js/personal.js` 의 `QUOTE_DATA` 도 같이 바꿉니다
- 예전 견적서 사이트(https://hyunbin5786.github.io/sayuwon-invoice-quotation/, 저장소 `sayuwon-invoice-quotation`)도 그대로 열리지만, 이 시스템은 `document/` 를 씁니다

## 2. 공통 규칙

- **로그인**: 이름 + 사번. 멤버 목록(공유 시트 `members` 탭)과 맞아야 들어갑니다 (이름 띄어쓰기는 무시). 이미 로그인한 브라우저도 첫 화면을 열 때 다시 확인하고, 멤버에서 빠졌으면 로그아웃. 로그인하지 않고 다른 화면을 열면 첫 화면으로. 멤버 목록은 저장소 코드에 두지 않습니다
- **헤더**: 모든 화면 위쪽 초록 줄(높이 50px)이 같은 순서입니다. 「☰ 메뉴」 · 「사유원 운영 보조 시스템」 › 지금 화면 이름 · 👤 로그인한 이름 · 「나의 할일」 → 그 다음에 그 화면의 버튼(한/A 등). 모양 맞춤은 `css/menu.css` 의 `header:has(> .smenu-btn)` 규칙 하나로 (화면마다 CSS를 고치지 않아도 됨)
- **날짜 칸**: 칸 안에 `2026-12-05 (토)`. 누르면 달력, 달력을 연 뒤 한 번 더 누르거나 숫자를 치면 직접 입력(`2026-12-05` · `12/5` · `1205` · `12월 5일`, 연도가 없으면 올해 · 지났으면 내년). 새로 만드는 날짜 칸도 이 방식
- **한글 먼저**: 이름 · 업체 · 담당자 · 과업 칸은 들어가면 늘 한글부터 (입력기가 영문이어도 두벌식으로 조합). 영어는 한/영 키 · Shift+Space (`js/ime.js`). **헤더 「한/A」 버튼은 화면에서 숨김**(2026-11-18, 기능은 그대로)
- **메모 칸은 스크롤 없이 자동으로 늘어남** (2026-11-18): 줄이 늘면 칸이 아래로 넓어지고, 지운 만큼 다시 줄되 지금 크기(손으로 맞춘 크기)보다 작아지지는 않음 (`js/keepsize.js`)
- **연락처**: 빈 칸을 누르면 `010-`, 치는 동안 `010-0000-0000` 모양 (010- 다음 숫자 4개를 치면 바로 `-`). **단체 화면은 어떤 번호든 자릿수에 맞춰 `-`** (2026-11-18): 010-1234-5678 · 010-123-4567 · 02-123-4567 · 02-1234-5678 · 031-123-4567 · 031-1234-5678 · 070 · 0505-123-4567 · 1588-1234. 자동으로 들어간 `010-` 뒤에 0으로 시작하는 번호(02 · 031 …)를 치면 010을 저절로 뗌 (1588 같은 대표번호는 010- 을 지우고 치기)
- **시각 칸**: 키보드로 치지 않고 **누르면 시 · 분 목록이 떠서 스크롤로 고름** (**시는 06시 ~ 19시** = 사유원 운영 시각, 이미 적힌 시각이 밖이면 그 시도 목록에 · 분은 5분 단위, `js/timepick.js` 의 `H_MIN` · `H_MAX`). 입장 · 퇴장 · 몽몽마방 · 프로그램 시작/끝 · 사전답사 입장시각 · 예약 현황 직접 추가 시간대 · 사고 시각. 시작을 고르면 끝(+1시간)이 자동인 곳은 그대로
- **빠른 입력**: 글자를 치는 칸(메모 · 이름 · 이메일 · 비고 · 담당 · 문의 내용 · 과업 메모)은 값은 바로 넣고, 화면 다시 그리기는 치기를 멈추고 0.35초 뒤 한 번 (칸을 나가면 바로). 통화 메모와 같은 방식
- **입력 칸 예시(예) …)는 넣지 않음** (2026-11-18 모두 뺌 · 필요한 곳만 요청 받아 넣기)
- **팀 비밀번호**: 공유 기록을 읽고 쓰려면 필요. Apps Script 스크립트 속성 `PASSCODE` 에만 있고 저장소에는 없습니다. 한 번 넣으면 그 브라우저에 기억
- **개인정보**: 고객 이름 · 연락처가 들어간 파일 · 데이터는 저장소에 넣지 않습니다 (공유 시트 · 각자 브라우저에만)

## 3. 메뉴

**메뉴 = 모든 화면 헤더 맨 앞의 「☰ 메뉴」** (`js/menu.js` · `css/menu.css`, 2026-11-18). 누르면 왼쪽에서 아코디언 메뉴가 화면 위로 뜨고 뒤는 회색으로 가려집니다 (화면을 밀지 않음). 바깥 · × · Esc 로 닫기, 지금 화면은 메뉴에 표시. **첫 화면에서는 로그인했으면 메뉴가 왼쪽에 붙어 펼쳐짐**(회색 가림 없음 · 묶음도 모두 펼침 · 대시보드는 메뉴 너비 300px 만큼 옆으로 좁혀짐 · × / ☰ 로 접고 펴기 · 좁은 화면은 위에 뜸, `html.smenu-dock`). 첫 화면에서 로그인 · 로그아웃하면 메뉴를 다시 그리려고 새로고침. 메뉴 맨 위는 초록 띠 없이 베이지 배경에 「메뉴」와 ×, 항목 아래 회색 설명도 없음 (2026-11-18). **나의 할일은 메뉴에 없고 모든 화면 헤더의 「나의 할일」 버튼**(팝업, 네이버 이관 · 견적서 화면에도 menu.js가 붙임). 묶음을 누르면 펼치고 접으며 펼친 상태는 브라우저에 기억. 팝업 안(나의 할일 등)에서는 안 뜸. 첫 화면은 **대시보드(모두의 할일)**만, 로그인하지 않았으면 로그인 칸과 **예약현황 공유** (메뉴에도 그것만).

### 5-6. 추후 과업 · 수정 기록

- 과업마다 오른쪽 **「저장」** 버튼: 고치던 칸(제목 · 마감일 · 메모)을 확정하고 바로 저장. 자동 저장도 그대로 (마감일 · 자동 과업 제목을 바꾼 것도 변경으로 쳐서 자동 저장 · 수정 기록에 「[과업] … 마감 …」)
- 예약상담에는 자동 과업이 없고(사전답사 전산 예약만), 직접 추가한 과업은 씁니다
- **전산 내역 대조 (총 금액 · 할인)** (가예약 · 예약확정이면 「전산 예약」과 함께 늘 생김): 전산에 예약을 넣은 뒤 전산 내역을 붙여 넣으면, 예약 내용으로 계산한 **할인 합계**(할인 버튼 % + 기타 할인)와 **총 금액**을 전산 내역과 비교해 둘 다 같으면 **저절로 완료**, 다르면 열린 채로 어디가 다른지(예약 ○원 / 전산 ○원) 보여 줌. 전산 내역을 다시 붙여 넣거나 예약을 고치면 다시 비교. 직접 체크는 안 됨. 「전산 내역 합계」 아래에도 같은 ✓ / ✗ 표시
- 자동 과업: 사전답사 전산 예약 · 미정 항목 확인 연락(답변일) · 현장 결제 인원 확인 연락(전주 목요일) · 몽몽마방 식당에 시간 확인 · 몽몽마방 메뉴 선택 · 프로그램 · 굿즈 담당 입력 · 담당자에게 일정 전달(개별 · 시간 프로그램이 있으면 방문일이 있는 주 월요일, 굿즈만이면 방문 전날) · 굿즈 준비(방문 전날) · 전산 예약 · 전산 예약 수정 · 견적서 발급 · 거래명세서 발급 · 세금계산서 발행(사업자등록증 올리기) · 결제링크 전송 · 입금 확인(결제링크 보낸 다음날) · **전산 예약 수정은 전산 비고 문구(`erpNote`)가 바뀐 경우에만**(2026-11-18: 담당자 이름 · 연락처 등 비고에 안 들어가는 것은 과업을 만들지 않음 · 예전에 그렇게 생긴 과업은 예약을 열면 정리) · **나의 할일 · 대시보드 · 마감 알림도 화면과 같은 기준**(2026-11-18 `settleTasks` · 대시보드 `doneByRec`): 삭제한 과업 · 전산 등록된 전산 예약 · 전송 일시가 있는 결제링크 전송 · 입금 일시가 있는 입금 확인 · 담당이 다 찬 프로그램 담당 · 하위 과업이 모두 체크된 과업 · 예약취소 예약의 과업은 「오늘 마감」으로 세지 않음. 예약을 열면 화면의 과업 상태를 과업만 조용히 저장(`syncSavedTasks`, 수정 기록에는 안 남김)
- **현장 결제 인원 확인 연락** 과업에는 안내 멘트(「안녕하세요, 사유원입니다 …」)를 넣지 않음 (2026-11-19)
- **다음주 예약 점검 (매주 목요일)** (2026-11-19, `weekTask`): 나의 할일 › 단체 · 전체 탭의 「추후 과업 (단체)」 목록 맨 위에 과업 한 줄(따로 칸 없음, 과업 수에도 더함). 가장 가까운 지난 목요일(오늘이 목요일이면 오늘) 기준 다음 날부터 7일(금 ~ 다음 목)의 내가 영업 담당인 예약(가예약 · 예약확정)의 단체 이름을 세부 과업으로, 체크하면 공유 기록(통화 구분 「주간점검」, 사람 · 주마다 한 줄)에 저장. 단체 이름을 누르면 그 예약 열기. 마감 = 그 목요일(오늘 = 노랑, 지나면 빨강), 모두 체크하면 목록에서 빠짐. 첫 화면 대시보드 「단체고객 전화」에도 한 줄(「다음주 예약 점검 · 11월 20일 (금) ~ 11월 26일 (목) · n/m」 · 영업 담당 · 마감 = 그 목요일, 다 체크하면 빠짐 · 누르면 나의 할일 단체 탭) — portal.js dashRecs
- **사전답사 전산 예약** 과업에 전산 비고 문구 `단체명 사전답사` · 답사 1명은 무료라 **2명 이상이면 `/(인원 − 1)명 현장결제 필요`** (예: 2명 → `가상가족센터 사전답사/1명 현장결제 필요`, 1명 → `가상가족센터 사전답사`. 자동 · 직접 고칠 수 있음 · 「비고 문구 복사」)
- **「사전답사」 버튼** (예약 내용 위, 견적서 앞 · 같은 모양의 체크 + 버튼): 팝업 (다른 입력 칸과 같은 모양): **1행 성명 · 연락처, 2행 일자 · 인원 · 입장시각** (성명 기본 = **단체명(담당자 이름)**, 연락처 기본 = 담당자 연락처 · 입장시각 1000 → 10:00 · 예전 「시간」도 읽음). 저장하면 체크가 켜지고 추후 과업 「사전답사 전산 예약」(메모 = 답사 정보, 메모를 직접 고치지 않았으면 답사 정보를 바꿀 때 같이 바뀜). 체크를 풀거나 「답사 없음」이면 답사 정보를 지움. 단체상담 입력의 답사 요청 정보도 같은 칸으로 들어가고(성명 · 연락처가 없으면 담당자) 과업이 자동으로 생김. 시트 비고 칸 `사전 답사 성명: … , 일자: … , 인원: n명 , 시간: …`
- **과업 한 줄**: **체크 칸을 눌러야 완료**(제목을 눌러도 완료되지 않음). **제목을 누르면 고칠 수 있음** (자동 과업도 · Enter = 확정, Esc = 되돌리기, 비우면 원래 제목) — 개인고객 화면도 같음

- **전산 비고 금액 문구** (`760,000원(사유원) 0원(신라) 현장결제 필요`): **현장 결제**(또는 결제링크 + 현장 재결제)일 때만 넣습니다. 세금계산서 · 결제링크 · 기타 · 미정이면 넣지 않음. 몽몽마방 결제가 **마방**이면 몽몽마방 식사 금액은 빼고(손님이 식당에서 결제), **사무실**이면 넣음. 사유원 = 관람, 신라 = 그 밖(식사 · 프로그램 · 굿즈). 전산 내역을 붙여넣었는데 전산에 없는 품목(예: 몽몽마방 식사)은 예약 칸으로 계산해 더함
- **수정 기록** (2열 예약 현황 아래, **늘 접혀 있고** 「▸ 수정 기록 n건」을 누르면 펼침): 바뀐 칸마다 값의 흐름(`관람 인원 20 → 22 → 25`) · 시각 · 고친 사람. 한 번 여는 동안의 자동 저장은 한 줄에 모임. 줄마다 **이 버전으로 돌아가기**(미리보기)

## 8. 품목관리 (메뉴 6) (`#catalog`)

예약 상품 · 가격 · **과세(신라) · 비과세(사유원)**(정상가를 나눠 적는 품목만: 비과세 = 입장료 = 사유원 몫, 과세 = 신라철강 몫) · 할인 대상 · 구분. 구분 순서 · 버튼: **전체 › 관람 › 관람+식사 › 식사 › 단체(시간) › 단체(개별) › 굿즈** (몽몽마방 메뉴 구분은 없애고 식사로). 고치고 2초 뒤 자동 저장(공유 Apps Script). 단체 · 개인고객 화면의 가격 · 몽몽마방 메뉴 · 프로그램 칸이 이 목록을 따라갑니다.

### 8-1. 품목 분류 지침 (2026-11-18 · 꼭 지킬 것)

- **품목의 구분은 품목관리 한 곳에서 정합니다.** 견적서 / 거래명세서 · 단체예약 · 스마트스토어 발송 보고가 모두 품목관리의 **구분**을 그대로 따라갑니다. 구분을 바꾸면 화면마다 따로 고치지 않습니다.
- **굿즈** = 품목관리에서 구분이 「굿즈」인 품목. 단체예약 품목 고르기의 **굿즈 묶음**에 **품목관리 품명 그대로** 나오고, 줄 모양도 굿즈와 같습니다(수량 · 담당 · 비고, 시작 · 끝 없음). 견적서도 굿즈로 분류합니다.
- **음료쿠폰(가가빈빈) · 음료쿠폰(몽몽차방)은 굿즈**로 진행합니다 (품목관리에서 굿즈로 바꿈).
- **같은 품목은 한 번만**: 예전부터 전용 칸이 있던 품목(음료쿠폰(가가빈빈) = 시트 열 `가가 바우처`, 저장 키 `gaga`)은 굿즈 묶음에서 **그 칸으로 한 줄**만 나옵니다. 예전에 굿즈로 따로 넣어 두었던 같은 품목은 예약을 열 때 그 줄로 합쳐집니다.
- **예약 현황 「음료쿠폰」**: 음료쿠폰(가가빈빈) 줄과, 굿즈로 넣은 음료쿠폰(몽몽차방 등)을 모두 모아 보여 줍니다.
- 새로 굿즈를 만들 때는 **품목관리에 「굿즈」로 추가만** 하면 됩니다(코드 수정 없음). 예전 전용 칸이 있는 품목을 굿즈로 옮길 때만 `js/group.js` 의 `COUPON_IN_GOODS` 에 그 키를 넣습니다(`PROG_SRC` 의 품목 이름으로 짝지음).
- 코드: `catalogItems()`(품목관리 구분 = `edits[품목].kind` 가 먼저) → `goodsItems()`(구분이 굿즈) → `itemSelectHTML()` 굿즈 묶음 · `goodsKeyOf()`(굿즈 품목 → 예전 칸) · `openRecord()` 합치기 · `bookRows0()` 음료쿠폰 모으기. 견적서는 `document/js/document.js` 가 `edits` 의 kind 를 덮어써서 같은 구분.

- **오늘 마감**인 과업은 노란색(그 과업 줄 + 카드), 마감이 지난 과업은 빨간색
- 줄을 누르면 단체는 단체 화면에서 그 예약(`group.html?open=예약ID`), 개인은 개인고객 화면에서 그 통화
- 개인고객 화면에서 과업을 체크하면 시트에 올라가기 전이라도, 올라간 직후라도 나의 할일에서 바로 빠짐 (개인고객 화면이 가진 내용과 단체 화면이 가진 내용 중 수정 일시가 더 새로운 쪽을 씀. 다른 창에 열린 나의 할일도 바로 다시 그림)

## 11. 공유 기록 (구글 시트 · Apps Script)

다른 JS 파일도 같은 모양입니다: `personal.js`(공유 기록 → 날짜 칸 → 칸 · 과업 → 구분 · 보고 → 저장 · 자동 저장 → 목록 · 통화 기록 전체 · 삭제 → 마감 알림 · 나의 할일 숫자 · 보고 글자 미리보기 · 삭제 확인 · 노란 점) · `portal.js`(로그인 → 멤버관리 → 품목관리 → 대시보드) · `ops.js`(화면별 칸 `BOARDS` → 공유 기록 → 목록 → 추가 · 고치기 → 세부 과업).

### 14-4. 데이터 (공유 시트 `calls` 한 줄 = 한 기록)

- **열**: `apps-script/group-intake.gs` 의 `COLS` (id · 저장 일시 · 통화 시작 · 받은 사람 · **통화 구분** · 요약 · 방문일 · 업체 · 담당 · 결제 · … · 고객 담당자 · 연락처 · 이메일 · 입장 · 퇴장 · … · **비고(memo)** · 통화 메모(note) · 수정 일시 · 삭제 · **수정 기록(history)**). 열에 없는 값은 비고 · 수정 기록 칸에 넣습니다
- **통화 구분(callType)으로 종류를 나눔**: `예약상담` · `가예약` · `예약확정` · `예약취소`(예전 `단체예약` · `상담` · `예약접수` · `공식예약`) = 단체 (예약취소는 대시보드 · 다음날 준비 · 개인고객 알림에서 빠짐) / `개인고객` / `개인업무` · `분실물` · `사고` · `재고` · `스마트스토어` = 운영보조 / 특별한 줄: `mabangdb`(몽몽마방 목록) · `bookdb`(예약 현황 직접 추가) · `pcats`(개인 구분, `개인구분`) · `spdisc`(특별 할인 종류, `특별할인설정`)
- **비고 칸(memo)** = `이름 값 / 이름 값 / …` (칸 구분은 ` / `). `MEMO_PARTS` 목록 + 특별 할인 · 추가 프로그램 · 프로그램 담당/시간대/코스/장소 · 담당자 메모(`담당자 메모 0=… ¦ 1=…`). 읽기는 `unpackExtra()`, 쓰기는 `packExtra()` — **새 값을 저장하려면 `FIELDS`(숨은 칸 `굿즈` 묶음) + `MEMO_PARTS` 에 한 줄씩**
- **수정 기록 칸(history, JSON)**: 단체 `{h:[수정 기록], tasks:[과업], erp:[전산 내역], memos:[담당자에게 메모]}` · 개인고객 `{h, tasks, cat, reportTo, reserved}` · 운영보조 `{kind, d:{내용}, log:[]}`
- **과업 하나**: `{id, title, done, doneAt, doneBy, due, dueSet, memo, at, subs:{생성:true…}, xsubs:[{id,title,done}], custom, removed, manualDone, noteEdit}` — 자동 과업 id 는 `AUTO_TASKS` 의 키, 직접 추가는 `custom:true`, 지운 자동 과업은 `removed:1`(다시 안 생김)
- **Apps Script 를 고치면** 사용자가 새 버전으로 배포해야 합니다. 화면만 고칠 땐 필요 없음
